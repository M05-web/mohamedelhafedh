🌍 1. Vue d'ensemble du projet

WerguiYaram (« prends soin de ta santé » en Wolof) est une plateforme web médicale complète destinée au marché sénégalais. Elle connecte patients, médecins et administrateurs hospitaliers sur une interface unifiée, moderne et sécurisée.

3Rôles Utilisateurs
25+Pages & Composants
8Tables Supabase
17Routes Protégées
10Spécialités Médicales
100%RLS Sécurisé
Objectifs principaux
Pour les Patients
  • Trouver et réserver un médecin en ligne
  • Gérer ses rendez-vous et leur historique
  • Consulter et modifier son profil médical
  • Voir la liste de ses médecins suivis
Pour les Médecins
  • Gérer son agenda et ses disponibilités
  • Confirmer ou rejeter des rendez-vous
  • Consulter la liste et les dossiers patients
  • Rédiger et archiver ses consultations
Pour les Admins
  • Tableau de bord avec statistiques globales
  • Gestion des utilisateurs (patients, médecins)
  • Gestion des spécialités médicales
  • Supervision de tous les rendez-vous
Technique
  • Authentification sécurisée (Supabase Auth)
  • Row Level Security (RLS) sur toutes les tables
  • Déploiement Vercel avec routes SPA
  • Interface responsive desktop + mobile

Flux d'authentification
User Login
    │
    ▼
supabase.auth.signInWithPassword(email, password)
    │
    ▼
SecurityService.getUserRole(user)
    │  → Cherche dans auth.users.user_metadata.role
    │  → Fallback: cherche dans table profiles
    │
    ├── role === 'patient'  → navigate('/dashboard')
    ├── role === 'doctor'   → navigate('/doctor-dashboard')
    └── role === 'admin'    → navigate('/admin-dashboard')
Flux d'inscription
User Register
    │
    ▼
supabase.auth.signUp({ email, password, data: { role, full_name } })
    │
    ├── Trigger PostgreSQL: handle_new_user() [SECURITY DEFINER]
    │       → INSERT INTO profiles (id, full_name, email, role)
    │       → IF role='patient': INSERT INTO patients (user_id)
    │       → IF role='doctor':  INSERT INTO doctors (user_id)
    │
    └── Frontend (si session disponible): upsert manuel de sécurité
            → Évite tout timeout si le trigger est lent

Trigger d'inscription automatique (SECURITY DEFINER)
CREATE OR REPLACE FUNCTION handle_new_user()
RETURNS TRIGGER LANGUAGE plpgsql SECURITY DEFINER AS $$
BEGIN
  -- 1. Créer le profil
  INSERT INTO public.profiles (id, full_name, email, role)
  VALUES (
    NEW.id,
    NEW.raw_user_meta_data->>'full_name',
    NEW.email,
    COALESCE(NEW.raw_user_meta_data->>'role', 'patient')
  ) ON CONFLICT (id) DO NOTHING;

  -- 2. Créer patient OU médecin selon le rôle
  IF NEW.raw_user_meta_data->>'role' = 'doctor' THEN
    INSERT INTO public.doctors (user_id)
    VALUES (NEW.id) ON CONFLICT DO NOTHING;
  ELSE
    INSERT INTO public.patients (user_id)
    VALUES (NEW.id) ON CONFLICT DO NOTHING;
  END IF;

  RETURN NEW;
END;
$$;

-- Déclenché après chaque création d'utilisateur
CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE FUNCTION handle_new_user();
Politiques RLS — Principe

Chaque table dispose de RLS activé. Le script FIX_PRESENTATION.sql supprime toutes les politiques conflictuelles et recrée un set cohérent. Pour la présentation, des politiques ouvertes sont utilisées :

-- Politique ouverte (développement/présentation)
CREATE POLICY "auth_all" ON appointments
  FOR ALL TO authenticated USING (true) WITH CHECK (true);

-- Politique restrictive recommandée (production)
CREATE POLICY "patient_own" ON appointments
  FOR SELECT TO authenticated
  USING (patient_id = (SELECT id FROM patients WHERE user_id = auth.uid()));

Composant PrivateRoute
// src/global/PrivateRoute.jsx
const PrivateRoute = ({ children, requiredRoles }) => {
  const { user, role, loading } = useAuth();

  if (loading) return <LoadingSpinner />;

  // Non connecté → redirection vers login
  if (!user) return <Navigate to="/login" replace />;

  // Rôle non autorisé → redirection vers login
  if (requiredRoles && !requiredRoles.includes(role))
    return <Navigate to="/login" replace />;

  return children;
};
SecurityService — Résolution du rôle
// src/global/security.js
export const SecurityService = {
  getUserRole: async (user) => {
    // 1. Vérifier user_metadata (le plus rapide, sans requête DB)
    const metaRole = user?.user_metadata?.role;
    if (metaRole) return metaRole;

    // 2. Fallback: chercher dans la table profiles
    const { data } = await supabase
      .from('profiles')
      .select('role')
      .eq('id', user.id)
      .single();

    return data?.role || 'patient';
  }
}
🔧 8. Problèmes Résolus & Décisions Techniques
Timeout à l'inscription — Erreur {} vide Critique

Cause racine: Le trigger PostgreSQL utilisait ON CONFLICT (user_id) mais les tables patients et doctors n'avaient aucune contrainte UNIQUE sur la colonne user_id. PostgreSQL lançait une erreur interne silencieuse que Supabase retournait sous forme d'objet vide {}.

Correction: Ajout des contraintes UNIQUE via ALTER TABLE. Remplacement de ON CONFLICT par IF NOT EXISTS dans le trigger. Ajout d'un fallback upsert manuel côté frontend.

Patients invisibles dans le dashboard médecin Majeur

Cause racine: 17 fichiers SQL successifs avaient créé des politiques RLS contradictoires et en conflit. Certaines politiques se bloquaient mutuellement, rendant les jointures entre tables impossibles.

Correction: Suppression de toutes les politiques via une boucle sur pg_policies. Recréation d'un set unique de politiques cohérentes dans un seul fichier FIX_PRESENTATION.sql.

Crash au login — SecurityService non importé Majeur

Cause racine: login.jsx utilisait SecurityService.getUserRole() mais l'import correspondant était absent, causant un ReferenceError au runtime.

Correction: Ajout de import { SecurityService } from '../../global/security' dans login.jsx.

Crash DoctorPatients — Button antd non importé Mineur

Cause racine: Le composant utilisait <Button> d'Ant Design dans le JSX mais il n'était pas inclus dans la déstructuration des imports.

Correction: Ajout de Button dans la liste des imports Ant Design de DoctorPatients.jsx.

Crash adminDashboard — dayjs().fromNow() non défini Majeur

Cause racine: Le code utilisait dayjs().fromNow() qui requiert le plugin relativeTime enregistré explicitement. Sans ce plugin, la méthode n'existe pas → TypeError.

Correction: Remplacement de toutes les occurrences de .fromNow() par .format('DD/MM/YYYY HH:mm').

17 fichiers SQL conflictuels → 1 fichier définitif Architectural

Cause racine: Accumulation de scripts SQL successifs (01_extensions, NUCLEAR_CLEANUP_FIX, ULTIMATE_RLS_FIX, FINAL_DATABASE_HARDENING, etc.) créant des politiques contradictoires.

Correction: Suppression de tous les anciens fichiers. Création de supabase/FIX_PRESENTATION.sql — script unique et idempotent couvrant toutes les étapes.
